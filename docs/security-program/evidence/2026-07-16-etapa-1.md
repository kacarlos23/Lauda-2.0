# Evidencia tecnica - Etapa 1

Data: 2026-07-16
Escopo: contencao tecnica de autenticacao, reset, rate limiting e erros
Status: codigo verificado; operacao produtiva bloqueada

## Diagnostico inicial

- O working tree ja continha uma implementacao parcial nao versionada de reset
  por HMAC, rate limiting, SMTP e elegibilidade canonica.
- `npm start` nao definia `NODE_ENV=production`, permitindo iniciar o launcher
  publico com defaults locais.
- O `.env` local contem somente `DATABASE_URL`; secrets produtivos, Redis e SMTP
  nao estao provisionados nesta maquina.
- O launcher Cloudflare inspecionado tem exatamente um hop reverso local
  (`cloudflared`) e vincula a API a `127.0.0.1`.
- Essa hipotese e valida somente quando API e `cloudflared` sao processos no
  mesmo host confiavel, sem proxy adicional. Nao cobre container separado,
  load balancer, ingress, proxy intermediario ou acesso direto alternativo.
- Nao havia prova explicita de concorrencia do reset, expiracao, Redis
  compartilhado ou limites independentes por IP e identificador.

## Verificacoes executadas

- `npm run build`: aprovado.
- `npx prisma validate`: aprovado.
- Unitarios focados de reset, limiter, config e logs: 28 aprovados.
- Integracao de autenticacao/reset com PostgreSQL e 20 migrations: 17 aprovados.
- Integracao Redis com duas instancias de store: 1 aprovado.
- Suite backend completa: 21 suites e 162 testes aprovados.
- Revisao final focada: 7 suites e 58 testes aprovados.
- Wrappers de development/production: sintaxe validada com `node --check`.
- `npm start` sem secrets produtivos: bloqueado como esperado com
  `JWT_SECRET is required in production`.

Uma primeira execucao conjunta excedeu o timeout de pull/start do container
Redis e contaminou o teardown seguinte. O hook foi ajustado para 120 segundos;
Redis e autenticacao foram reexecutados isoladamente e aprovados.

Uma primeira tentativa da suite completa foi encerrada pelo timeout externo de
seis minutos sem relatorio Jest e foi tratada como inconclusiva. Os processos e
containers do teste foram encerrados; a suite foi repetida com janela adequada
e concluiu em 182,562 segundos com 21/21 suites aprovadas.

## Compatibilidade e rollback

- Challenges legados sao invalidados pela migration e nao podem ser restaurados.
- `npm start` deixa de aceitar defaults de desenvolvimento.
- Producao exige Redis, SMTP, quatro secrets independentes e failure mode closed.
- O launcher Cloudflare local usa `TRUST_PROXY_HOPS=1` e bind `127.0.0.1` sob a
  hipotese documentada; isso nao valida a topologia produtiva definitiva.
- O rollback de schema esta documentado no README da migration e nunca autoriza
  retorno ao PIN em claro.

## Bloqueios operacionais

- Provisionar Redis produtivo com TLS, autenticacao, isolamento e monitoramento.
- Selecionar/aprovar provedor SMTP e comprovar entrega, regiao, DPA e alertas.
- Provisionar secrets independentes por ambiente em secret manager e definir
  rotacao do pepper e da chave HMAC do limiter.
- Confirmar `trust proxy` na topologia produtiva final fora do launcher local.
- Revisar backup e executar plano de rollback em staging.
- Nomear owners/aprovadores ainda marcados como TBD.

Enquanto esses itens permanecerem abertos, a Etapa 1 nao deve ser declarada
operacionalmente concluida nem liberar producao com dados reais.
